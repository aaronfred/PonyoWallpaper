# v1.4.0 壁纸源扩展方案

> 目标：首页支持「切换壁纸源」，可单选或多选，并补充 2–3 个优质壁纸源。  
> 日期：2026-09-22　状态：待确认

## 一、背景：为什么要做这件事

当前只有一个源（wallhaven），而 wallhaven **在国内完全不可达**：

| 目标                      | 实测                                         |
| ----------------------- | ------------------------------------------ |
| `wallhaven.cc`          | ✗ 直连超时 15s（DNS 污染，解析到 103.252.114.61）      |
| `th.wallhaven.cc`       | ✗ 直连超时 15s                                 |
| 内置默认反代                  | ⚠ **持续 503**（根路径 200 说明 Worker 活着，但上游通道挂了） |
| 用户自建反代 `ikankan.eu.org` | ✗ 502 / 503                                |

**结论：换源不是"增加选择"，而是恢复可用性的必要手段。**

## 三、注册阻塞项（需你处理）

需要 Key 的三个源，注册都要**邮箱验证**。当前可用邮箱状态：

| 邮箱方案                               | 状态                                            |
| ---------------------------------- | --------------------------------------------- |
| Agent Mail（`guanjia@claw.163.com`） | ⚠ **工具返回「Agent 邮箱尚未开通」**，需你在「更多 → 我的邮箱」面板完成开通 |
| ClawEmail CLI                      | ⚠ 仅有技能文档，CLI 未安装、无授权链接                        |

**因此本方案分两阶段交付：**

- **阶段一（现在就能做）**：Bing + Picsum/360 免注册源 + 源抽象层 + 首页切换 UI → **立即可用，不再依赖任何被墙服务**
- **阶段二（你开通邮箱后）**：注册 Unsplash / Pexels / Pixabay 取 Key → 填入设置页 → 三个源自动生效

> 阶段二也可以在设置页让用户自己填 Key（无需我注册），三处输入框留空即视为该源未启用。

## 四、技术设计

### 4.1 源抽象层

```
Core/Sources/
├── IWallpaperSource.cs     统一接口
├── WallhavenSource.cs      现有逻辑迁移（行为不变）
├── BingSource.cs           免注册 ✓
├── UnsplashSource.cs       需 Key
├── PexelsSource.cs         需 Key
├── PixabaySource.cs        需 Key（备选）
└── SourceRegistry.cs       注册表 + 启用状态 + 多选混合
```

```csharp
public interface IWallpaperSource
{
    string Key { get; }                  // "bing" / "unsplash" ...
    string DisplayName { get; }          // "Bing 每日壁纸"
    bool NeedsApiKey { get; }
    bool IsConfigured(AppConfig cfg);    // Key 是否已填
    bool NeedsProxy { get; }             // wallhaven = true，其余 = false
    int MaxPageSize { get; }
    Task<IReadOnlyList<WallpaperItem>> SearchAsync(
        SourceQuery q, CancellationToken ct);
}
```

`WallpaperItem` 增加 `SourceKey` 字段，用于卡片角标与收藏去重（不同源可能有相同 id）。

### 4.2 多选混合策略

勾选 N 个源时，按源并发请求，各取 `PageSize / N` 条，合并后**交错排列**（round-robin）而非拼接，避免"前一半全是 A 源"。

单源失败不影响其他源 —— 部分成功即展示，全部失败才报错。

### 4.3 分类差异处理（核心设计）

#### 关键发现：不需要重新设计分类

现有 `Channels.cs` 的 23 个频道**每个都已携带 `Query`**，例如：

```
nature_landscape  "自然风光"  categories=100  "+landscape +nature"
anime_girls       "二次元少女" categories=010  "+anime +girls"
```

所以每个频道天然拥有三种查询表达，**无需新建分类体系**：

| 表达               | 取值                | 示例                   | 给谁用                         |
| ---------------- | ----------------- | -------------------- | --------------------------- |
| `WallhavenQuery` | 现有 `Query`（带 `+`） | `+landscape +nature` | wallhaven                   |
| `KeywordEn`      | `Query` 去掉 `+`    | `landscape nature`   | Unsplash / Pexels / Pixabay |
| `KeywordZh`      | 现成的 `Name`        | `自然风光`               | 支持中文查询的源                    |

#### 源能力声明

```csharp
public interface IWallpaperSource
{
    QueryFlavor Flavor { get; }   // 该源接受哪种查询表达
}

public enum QueryFlavor
{
    WallhavenTag,   // wallhaven：带 + 的标签语法 + categories 三位码
    PlainEn,        // Unsplash：纯英文关键词
    PlainEnOrZh,    // Pexels / Pixabay：英文，可选切中文
    None,           // Bing：完全不支持查询
}
```

| 源         | Flavor         | 说明                        |
| --------- | -------------- | ------------------------- |
| wallhaven | `WallhavenTag` | 沿用现有 `Query` + `Category` |
| Unsplash  | `PlainEn`      | 英文检索效果最好                  |
| Pexels    | `PlainEnOrZh`  | 官方支持中文检索                  |
| Pixabay   | `PlainEnOrZh`  | 官方支持中文检索                  |
| Bing      | `None`         | 只有每日一张，无查询能力              |

#### 匹配规则

1. 选中频道 → 各源按自己的 `Flavor` 取对应表达
2. **`Flavor == None` 的源不参与频道过滤** —— Bing 作为**独立的第 5 个频道组「每日精选」**，  
   用户选它就走 Bing；选风景/动漫等频道时 Bing 自动不参与（避免"动漫频道里冒出 Bing 风景照"）
3. 某源在某频道下返回空 → **不报错、不占位**，菜单中该源标注「该频道无结果」并置灰
4. 顶部**关键词搜索框** → 直接作为 `PlainEn/PlainZh` 传给所有 `SupportsQuery` 的源，支持任意词跨源搜索

#### 中文关键词开关

设置页加一项「使用中文关键词检索」（默认关）：

- 关：所有源用 `KeywordEn`
- 开：`PlainEnOrZh` 的源（Pexels/Pixabay）改用 `KeywordZh`，其余仍用英文

> 中文检索效果待 Key 到位后实测验证；若效果差则默认回退英文。

#### 为什么这不等于"削足适履"

| 方案             | 问题                                                                       |
| -------------- | ------------------------------------------------------------------------ |
| ❌ 硬性统一分类 ID    | 各源分类粒度不同（wallhaven 23 频道 vs 360 有 18 类 vs Unsplash 无分类），强行对齐要么丢信息要么大量空结果 |
| ❌ 每个源各自一套分类    | 用户要切换 4 套心智模型，多源混合时无法表达                                                  |
| ✅ **分类 → 查询词** | 4/5 的源支持自由文本检索，把统一频道翻译成各源查询词即可；不支持查询的 Bing 单独成组                          |

### 4.4 首页 UI

底部工具栏在「轮换频道」左侧新增 **「壁纸源」** 按钮：

```
[壁纸源(3)]  [轮换频道]  [间隔 60 分]  [分辨率]  [填充]  [排序]  [多屏]
    └─ 复选菜单（与「轮换频道」同款交互，可多选）
       ☑ Bing 每日壁纸        免注册
       ☑ Unsplash             ✓ 已配置
       ☐ Pexels               ⚠ 未配置 Key（点击去设置）
       ☐ Pixabay              ⚠ 未配置 Key
       ☐ Wallhaven            ⚠ 国内不可达
```

- 按钮文字显示已启用源数量
- 至少保留 1 个源，取消最后一个时提示
- 卡片左上角加来源角标（`Bing` / `U` / `P`），便于识别

### 4.5 设置页

在「代理管理」下方新&#x589E;**「壁纸源」**&#x533A;块：

```
Bing 每日壁纸        无需配置                     [启用 ✓]
Unsplash API Key    [______________________________]
Pexels API Key      [______________________________]
Pixabay API Key     [______________________________]
```

Key 以密码样式显示（点击"眼睛"可见），即时保存生效。

### 4.6 代理规则联动

`ProxiedHosts` 默认只有 wallhaven 三域名。新增源**默认不走代理**（实测均直连可达），  
但保留可配置 —— 若某源在某网络环境下需要代理，用户可自行加进规则。

## 五、风险与对策

| 风险                      | 影响           | 对策                                               |
| ----------------------- | ------------ | ------------------------------------------------ |
| Bing `idx` 上限           | 只能翻到约 1 年前的图 | 用 `idx` 随机化 + 记录已用日期，避免重复                        |
| 360 壁纸接口老旧（HTTP）        | 未来可能下线       | 定位为备选，不进首发                                       |
| Unsplash demo 档 50 次/小时 | 高频换图会限流      | 命中 429 时按现有「换链路」逻辑改为「换源」，正好复用 v1.3.0 的 429 处理    |
| 各源图片尺寸/比例不一             | 瀑布流错落        | 已有瀑布流自适应；Bing 固定 1920x1080 单独归一化                 |
| 多源混合后「收藏」与缓存 id 冲突      | 收藏错乱         | `WallpaperItem.SourceKey + Id` 作为复合主键，缓存目录按源分子目录 |

## 六、工作量与顺序

|  阶段 | 内容                                                  | 产出               |
| :-: | --------------------------------------------------- | ---------------- |
|  1  | 源抽象层 + `WallhavenSource` 迁移                         | 编译通过、现有功能零回归     |
