========================================================
反代搭建指引（通用版：Cloudflare Worker 或 自建服务器）
========================================================

【原理】
用一台"境内可直连"的服务做 wallhaven 全站反向代理：
· 应用请求  https://你的反代/api/v1/search?…   → 转发到 wallhaven.cc
· 应用请求  https://你的反代/th/lg/…           → 转发到 th.wallhaven.cc（缩略图）
· 应用请求  https://你的反代/w/full/…          → 转发到 w.wallhaven.cc（原图）
一次搭建，长期稳定；优先于一切代理。

========================================================
方案 A：Cloudflare Worker（免服务器，约 5 分钟，推荐）
========================================================
1. 打开 https://dash.cloudflare.com/sign-up 用邮箱注册（免费，无需绑卡）。
2. 控制台 → Workers & Pages → Create application → Create Worker。
3. 名称填 ponyo-mirror（随意）→ Deploy → Edit code。
4. 删除默认代码，粘贴下面这段，再点 Deploy：

--------------------------------------------------------
export default {
  async fetch(request) {
    const url = new URL(request.url);
    let target;
    if (url.pathname.startsWith('/th/')) {
      target = 'https://th.wallhaven.cc' + url.pathname.slice(3);
    } else if (url.pathname.startsWith('/w/')) {
      target = 'https://w.wallhaven.cc' + url.pathname.slice(2);
    } else {
      target = 'https://wallhaven.cc' + url.pathname + url.search;
    }
    const headers = new Headers();
    const ua = request.headers.get('User-Agent');
    if (ua) headers.set('User-Agent', ua);
    const key = request.headers.get('X-API-Key');
    if (key) headers.set('X-API-Key', key);
    const resp = await fetch(target, { method: request.method, headers });
    const out = new Headers(resp.headers);
    out.delete('content-security-policy');
    out.delete('x-frame-options');
    return new Response(resp.body, { status: resp.status, headers: out });
  }
}
--------------------------------------------------------

5. 部署后地址形如 https://ponyo-mirror.你的子域.workers.dev
6. 验证：浏览器打开 https://你的地址/api/v1/search?q=cat
   能看到 JSON（{"data":[...]}）即成功。
7. 应用 → 代理管理 → 反代地址 填入该地址（可填多行做备用）。

· 额度：免费版 100,000 请求/天，个人使用绰绰有余。
· workers.dev 域名若偶发被墙：Worker → Settings → Domains & Routes
  绑定自己的域名即可。

========================================================
方案 B：自建服务器（任何能访问 wallhaven 的 VPS）
========================================================
前提：一台境外 VPS（能直连 wallhaven），一个解析到它的域名。

【Caddy（最简单，自动 HTTPS）】
Caddyfile 内容：

    mirror.example.com {
        reverse_proxy /th/* https://th.wallhaven.cc {
            header_up Host th.wallhaven.cc
        }
        reverse_proxy /w/* https://w.wallhaven.cc {
            header_up Host w.wallhaven.cc
        }
        reverse_proxy https://wallhaven.cc {
            header_up Host wallhaven.cc
        }
    }

启动：caddy run --config Caddyfile

【Nginx】

    server {
        listen 443 ssl;
        server_name mirror.example.com;
        # ssl_certificate / ssl_certificate_key 按需配置
        location /th/ {
            proxy_pass https://th.wallhaven.cc;
            proxy_ssl_server_name on;
            proxy_set_header Host th.wallhaven.cc;
        }
        location /w/ {
            proxy_pass https://w.wallhaven.cc;
            proxy_ssl_server_name on;
            proxy_set_header Host w.wallhaven.cc;
        }
        location / {
            proxy_pass https://wallhaven.cc;
            proxy_ssl_server_name on;
            proxy_set_header Host wallhaven.cc;
        }
    }

========================================================
应用侧填写与优先级
========================================================
1. 设置 → 代理管理 → 反代地址：每行一个，按序尝试。
2. 优先级：直连 → 反代 → 用户代理 → 公共代理池。
   （按用户要求直连最优先；某一级失败自动切到下一级，成功后保持。）
3. hosts：默认不自动替换系统 hosts。仅当以上全部不生效时，
   才到 hosts 管理页手动添加 wallhaven IP 映射作为最后手段。
4. 公共代理池：每 6 小时或不足 2 个时自动重新优选（减少后台动作）。
