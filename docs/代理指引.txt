========================================================
Ponyo壁纸 · 代理指引（HTTP / SOCKS5 / 反代）
========================================================

一、三种类型的填写规则与示例
--------------------------------------------------------
设置页「当前代理」框支持三种写法，填入后实测通过即锁定使用；
清空则回到自动链路（直连 → 反代 → 手填代理）。

1) HTTP / HTTPS 代理
   格式：http://host:port
   带认证：http://user:pass@host:port
   示例：
     http://127.0.0.1:7890            （Clash 混合端口，可直接当 http 用）
     http://192.168.1.10:8080
     http://user:pass@1.2.3.4:8080

2) SOCKS5 代理
   格式：socks5://host:port
   带认证：socks5://user:pass@host:port
   说明：程序内置完整 SOCKS5 握手（RFC 1928/1929），支持用户名密码。
   示例：
     socks5://127.0.0.1:7890          （Clash SOCKS 端口）
     socks5://127.0.0.1:1080          （v2rayN / Shadowsocks 本地端口）
     socks5://user:pass@1.2.3.4:1080

3) 反向代理（反代）
   格式：https://你的反代域名         （只填根地址，不带路径、不带结尾斜杠）
   原理：反代不是传统"代理协议"，而是把 wallhaven 三个站点整体映射到一个
        境内可直连的地址，程序自动把请求改写到反代上：
          https://反代/api/v1/search?…  → wallhaven.cc        （API）
          https://反代/th/lg/…          → th.wallhaven.cc     （缩略图）
          https://反代/w/full/…         → w.wallhaven.cc      （原图）
   要求：反代必须按上面的路径规则转发（照抄下方搭建指南即可）。
   示例：
     https://my-mirror.example.workers.dev

二、内置默认代理
--------------------------------------------------------
程序内置了一个隐藏的默认反代（界面与日志中统一称「默认代理」，不显示地址）：
· 开箱即用，无需任何配置；
· 点「恢复默认代理」可随时清掉自填内容回到它；
· 延迟状态在设置页状态条实时显示。

三、常见本地客户端端口速查
--------------------------------------------------------
· Clash / Clash Verge : 混合端口 7890  → socks5://127.0.0.1:7890
· v2rayN              : SOCKS 10808 / HTTP 10809 → 对应填写
· Shadowsocks         : 本地 SOCKS 1080 → socks5://127.0.0.1:1080

四、反代搭建指南（Cloudflare Worker，免服务器约 5 分钟，推荐）
--------------------------------------------------------
1. 打开 https://dash.cloudflare.com/sign-up 用邮箱注册（免费，无需绑卡）。
2. 控制台 → Workers & Pages → Create application → Create Worker。
3. 名称随意 → Deploy → Edit code。
4. 删除默认代码，粘贴下面这段，再点 Deploy：

--------------------------------------------------------
export default {
  async fetch(request) {
    const url = new URL(request.url);
    let target;
    if (url.pathname.startsWith('/th/')) {
      target = 'https://th.wallhaven.cc' + url.pathname.slice(3);
    } else if (url.pathname.startsWith('/w/')) {
      target = 'https://w.wallhaven.cc' + url.pathname.slice(2);
    } else {
      target = 'https://wallhaven.cc' + url.pathname + url.search;
    }
    const headers = new Headers();
    const ua = request.headers.get('User-Agent');
    if (ua) headers.set('User-Agent', ua);
    const key = request.headers.get('X-API-Key');
    if (key) headers.set('X-API-Key', key);
    const resp = await fetch(target, { method: request.method, headers });
    const out = new Headers(resp.headers);
    out.delete('content-security-policy');
    out.delete('x-frame-options');
    return new Response(resp.body, { status: resp.status, headers: out });
  }
}
--------------------------------------------------------

5. 部署后地址形如 https://你的名字.你的子域.workers.dev
6. 验证：浏览器打开 https://你的地址/api/v1/search?q=cat
   能看到 JSON（{"data":[...]}）即成功。
7. 把该地址填入设置页「当前代理」框即可（实测通过后自动锁定）。

· 额度：免费版 100,000 请求/天，个人使用绰绰有余。
· workers.dev 域名若偶发被墙：Worker → Settings → Domains & Routes
  绑定自己的域名即可。

【方案 B：自建服务器（任何能访问 wallhaven 的 VPS）】
前提：一台境外 VPS（能直连 wallhaven），一个解析到它的域名。

Caddy（最简单，自动 HTTPS），Caddyfile：

    mirror.example.com {
        reverse_proxy /th/* https://th.wallhaven.cc {
            header_up Host th.wallhaven.cc
        }
        reverse_proxy /w/* https://w.wallhaven.cc {
            header_up Host w.wallhaven.cc
        }
        reverse_proxy https://wallhaven.cc {
            header_up Host wallhaven.cc
        }
    }

启动：caddy run --config Caddyfile

Nginx：

    server {
        listen 443 ssl;
        server_name mirror.example.com;
        # ssl_certificate / ssl_certificate_key 按需配置
        location /th/ {
            proxy_pass https://th.wallhaven.cc;
            proxy_ssl_server_name on;
            proxy_set_header Host th.wallhaven.cc;
        }
        location /w/ {
            proxy_pass https://w.wallhaven.cc;
            proxy_ssl_server_name on;
            proxy_set_header Host w.wallhaven.cc;
        }
        location / {
            proxy_pass https://wallhaven.cc;
            proxy_ssl_server_name on;
            proxy_set_header Host wallhaven.cc;
        }
    }

五、链路优先级与故障排查
--------------------------------------------------------
1. 自动链路优先级：直连 → 反代（自定义或内置默认）→ 手填代理；
   某一级失败自动切下一级，成功后保持。
2. 手填代理 = 明确意图：实测通过后锁定只用它，不自动切换；
   失效时状态条提示「不可用 ⚠ 换默认」。
3. 状态条延迟持续超高或不可达：点「恢复默认代理」回到内置默认代理。
4. 429 限流：程序自动换链路重试，无需处理。
5. 需要代理池管理 / 公共代理抓取 / 批量测速 / hosts 加速：
   使用独立工具 ProxyToolkit（代理工具箱，随本程序一并交付）。
